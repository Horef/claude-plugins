session-status-line

A compact status line above your prompt that shows the state of a chat at a glance: the model, how full the context is, your usage limits, and the cost. Install it and it works. The extras below are optional.

1. Reading the line

  1. 1State and model. ⏳ means a turn is running, ✅ means idle. Then the model and its thinking level (·H for high). A ⇄ in magenta for a few turns means you just switched model.
  2. 2Context. How full the chat's memory is. The bar is green under 50%, then yellow, orange, and red from 90% with a hint to type /compact.
  3. 35h and 7d limits. Your usage in the current five-hour and seven-day windows, with the time until each resets (⟳). Subscription accounts only. A ⚠ appears only when, at your pace so far, you would run out well before the reset.
  4. 4Helpers row. How much of your other subscriptions' quotas you have used (Kiro, Copilot, Codex, Antigravity as agy and Argon), and the limits of your other Claude accounts (here uni). A part with no data is hidden.
  5. 5Session row. The chat's cost, how long the last turn took (⏱), how many times it was compacted (🗜), files edited (✎), the prompt cache's time left (cache 42m), the cache warmer's switch (🔥), then turns and age.

Colour only shows fullness: things go gold, orange, then bold red as they fill. Labels and the session row stay dim. Dimmed figures with a ~ are old readings.

2. Install and check it works

  1. In Claude Code (desktop app or terminal), type: 
    /plugin install session-status-line --marketplace Horef/claude-plugins
    Confirm adding the marketplace if asked, then choose a scope (Install for you is the usual one).
  2. In chats that were already open, type /reload-plugins. New chats load it by themselves.
  3. The line appears above your prompt. If it does not, type /status-line on.
  4. For a short tour of what it can do, type /status-line help.

3. Going further: the optional extras

Each card works on its own. They follow one shape: what it is, whether you need it, what it needs, how to turn it on, how to check it, how to turn it off.

Quotas of your other subscriptionsKiro, Copilot, Codex, Antigravity and Claude extra usage in the line

What it is

Every five minutes the mod reads how much of each outside budget you have used and shows it in the helpers row: Kiro (credits this month), Copilot (premium credits this month), Codex (5-hour and weekly limits), agy and Argon (Antigravity), and extra (Claude credits spent past your plan's limits).

Do you need it?

If you use those subscriptions, it saves opening each tool's usage page. If you do not, nothing shows.

What you need

  • The tool installed and logged in on this computer: kiro-cli for Kiro (the line says Kiro log in when its login has gone stale), gh logged in for Copilot, codex for Codex, agy for Antigravity.
  • Claude extra usage needs a Claude subscription account.

Turn it on

  1. It is on by default. To read now, type /status-line quotas on.

Check it works

A part appears in the helpers row for each tool that is installed and logged in. A part that cannot be read keeps its last value, and shows a dim ~ before the number after 30 minutes.

Turn it off

Type /status-line quotas off. This also stops reading your other Claude accounts.

Your other Claude accountsSee each account's 5-hour and 7-day limits in one place

What it is

If you use more than one Claude account on the same computer (each with its own CLAUDE_CONFIG_DIR, for example a work or university plan beside a personal one), each chat shows the other accounts' limits as uni 5h 21% 7d 30% ⟳3d4h. Each session saves its own two windows to a small file in ~/.config/claude-accounts/ (no token, email or plan). Sessions of the other accounts read those files.

Do you need it?

Only if you have two or more accounts. With one account, nothing shows.

What you need

The mod installed under each account, and a session run in each, so each writes its file. Install it per account (see Updating: each account updates on its own).

Turn it on

  1. Install the mod under each account and start a chat in each.
  2. Optional: give an account a short name with /status-line account-label work. The default is the folder name without .claude-, so ~/.claude-uni is uni.

Check it works

The other account appears in the helpers row, dim if its reading is over 6 hours old. Type /status-line account-label with no name to see this account's label.

Turn it off

/status-line quotas off hides them. The extra live read (fresher figures, using the other account's login, never refreshing it) has its own switch: /status-line live off. On a Mac the first live read may ask for Keychain permission.

The cache warmerKeeps a waiting chat cheap to come back to

What it is

Claude remembers a chat's contents in a prompt cache for an hour on a subscription (5 minutes otherwise). Reading from the cache is far cheaper than reading the whole chat again. If you leave a long chat idle past that, the next message pays full price. The warmer prevents this: 50 minutes after the last request it sends one tiny side request over the conversation, so the cache stays alive. Nothing is added to your chat, and Claude is not woken into a turn. A warm costs about a tenth of a fresh read plus a few words, and counts toward your limits like any request.

Do you need it?

If you leave long chats waiting (a run that reports back every couple of hours, or a lunch break) and then continue them. It never revives a cache that has already lapsed, and it does not bother with a 5-minute cache.

What you need

Nothing installed. It belongs to the chat: a new chat, /clear or /resume starts with the warmer off.

Turn it on

  1. Press 🔥 in the band (on for 12 hours), or type /status-line warm.
  2. For other lengths: /status-line warm for 8h, /status-line warm until 07:30 or /status-line warm forever.
  3. To have it on in every chat, type /status-line warm every-chat on. It warms until 12 hours after the chat's last message.

Check it works

🔥 is lit and shows how many warms were sent, and cache 42m shows the time left. /status-line warm status gives the details. /status-line warm now sends one warm at once and says how much the cache served.

Turn it off

Type /status-line warm off. If it cannot keep the cache alive (a login problem, a lapse), it switches itself off and tells you.

Idle compactionShrinks a quiet, large chat before its cache runs out

What it is

To compact a chat is to replace its history with a summary. Claude Code does this to an idle chat shortly before its cache would lapse, and it cannot see the warmer. This option is the mod's own version: when on, a quiet chat of 200k tokens or more is compacted 5 minutes before its cache lapses, unless the warmer is keeping the cache alive. While the warmer is on and the cache is alive, the mod declines Claude Code's own idle compaction, and does the owed one itself later if the warmer stops.

Do you need it?

Only if you use the warmer on large chats and want to control when compaction happens. It is off by default.

What you need

Nothing. On Team and Enterprise accounts, Claude Code's built-in cc-plugin-sec-default plugin keeps compactions away from mods, so Claude Code's own idle compaction compacts about 54 minutes after your last message whatever the warmer does. There, also set "idleCompaction": false in your settings.json and use this option instead.

Turn it on

  1. Type /status-line warm idle-compact on, or use the ⓘ options row on the band.
  2. Optional: to turn off Claude Code's own idle compaction, put "idleCompaction": false in settings.json (in your CLAUDE_CONFIG_DIR, default ~/.claude).

Check it works

/status-line warm status and the ⓘ row say when a compaction is owed ("compacts at 08:25").

To close the ⓘ row, press ⓘ again or the × at the end of its first line.

Turn it off

/status-line warm idle-compact off. To keep a chat as it is instead of a compaction that is owed, type /status-line warm skip-compact.

Layout and lookOne line or rows, colours, plain characters

What it is

By default the line is one line when it fits and grouped rows (Claude, helpers, session) when it does not. You can force either, switch the line off, or change how it draws.

Do you need it?

If the line is too wide, too tall, or your terminal shows odd symbols.

What you need

Nothing. Your choices are remembered across chats.

Turn it on

  • /status-line auto (default), /status-line one or /status-line rows.
  • /status-line off hides the line; /status-line on brings it back.
  • In the shell you start Claude Code from: NO_COLOR=1 drops colours, SESSION_STATUS_ASCII=1 uses plain characters.

Check it works

The line changes at once. /status-line debug prints the version, the measured width and the last readings.

Turn it off

/status-line auto returns to the default.

4. Keeping it updated

Mods do not update by themselves unless you switch that on. You need only one of these:

  1. Turn on auto-update for the marketplace (once). In a chat, run /plugin, open the Marketplaces tab, pick horef-claude-plugins and turn auto-update on.
  2. Or update when the mod tells you. When a newer version exists the line shows an Update notice. The Update button fills the chat box with a request for Claude to run the update, and you press Enter. You can also type /status-line update to check now.

Then type /reload-plugins in chats that are already open. Each Claude account updates on its own. Full steps: Updating.

5. Troubleshooting

I see no line
Type /status-line on. If the command is unknown, the mod is not loaded: type /reload-plugins, or run claude plugin list in a terminal and look for session-status-line.
A budget I expect is missing
A part appears only when its tool is installed and logged in. For Kiro the line says Kiro log in when its login has expired: run kiro-cli login. Check that /status-line quotas is on.
Numbers are dim with a ~
That reading is old (over 30 minutes; other accounts, over 6 hours). Its tool could not be reached the last few times. Reconnect or log in again.
The line is cut off or too tall
Try /status-line rows or /status-line one. When rows do not fit, the mod drops parts, reset times first.
The warmer switched itself off
It does that on an error that will not pass, or when the cache lapsed (the computer slept). It says why in the chat. Switch it on again with /status-line warm.
Something else
Run /status-line debug and send the output.
