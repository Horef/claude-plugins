model-router

1. What it does

When you ask for something with several steps, model-router first makes a plan: a short list of steps, each marked with how hard it is. You approve the plan. Then each step runs on the cheapest Claude model that should do it well, and the pane shows what it cost and how much that saved. Your main chat's own model never changes.

Why this saves usage. A big model costs more for every word it reads and writes. Many steps (finding files, listing, summarizing) do not need it. The router sends those to a smaller model, in a separate short run called a subagent (a helper Claude started for one step), and keeps the big model for the hard parts. The saving it shows compares each step with your main chat's model doing the same work. It is an estimate from list prices.

Words used here. A level says how hard a step is: light (mechanical), standard (follows instructions), deep (needs judgment). Thinking (also called effort) is how long the model reasons: low, medium, high. A rung is one model-and-thinking pair on the ladder from cheap to strong, such as "Haiku low" or "Sonnet high".

2. Install and check it works

  1. In Claude Code (desktop app or terminal), type: 
    /plugin install model-router --marketplace Horef/claude-plugins
    Confirm adding the marketplace when asked, then choose a scope (Install for you is the usual one).
  2. In chats that were already open, type /reload-plugins. New chats load it by themselves.
  3. Look at the line under your prompt. You should see: 
    ⇄ Router on · rules go out with your next message · /router for the pane
    After your first message it changes to rules sent to opus (or whichever model your chat uses).
  4. Type /router to open the pane. The first line, the health line, should read: 
    Router on · helpers off
"Helpers off" is normal. Helpers are an optional extra: running steps on your other subscriptions. Without them, every step runs as a Claude subagent, which needs no setup. You can ignore this word until you read the Helpers card.

3. Your first plan (2 minutes)

The router only steps in when a request clearly has several steps. A one-step question ("what does this function do?") gets no plan, and that is on purpose. Paste this to try it:

Do this in three separate steps, and plan them first:
1. Find the five largest files in this folder.
2. Summarize in one sentence what each of them is for.
3. Tell me which one is most worth cleaning up first, and why.

Claude lists the steps and asks you to approve them. The question has three answers:

  • Run it: go ahead with the plan as it is now. Any edits you made in the pane are kept.
  • Run it, and auto-approve future plans: the same, and from now on plans run without asking. You can switch the asking back on in Settings.
  • Change the steps: the steps themselves need work (add, drop, split or reword). Nothing runs. Claude asks what to change, or, if you typed it under Other, revises right away.

While it runs. The status line shows progress dots and the running step with its model. In the pane, each step turns from ○ (planned) to ◐ (running) to ● (done). When a step finishes, Claude checks the result and gives it a verdict (ok, weak, overkill or cut short). That is how the router learns, see Verdicts and advice. The cost line fills in as the answers arrive.

4. Reading the pane (/router)

  1. 1Health line. Always first. Quiet when all is well. It turns into a ✗ message when something you switched on cannot run.
  2. 2A step row. Id and title on the first line. On the second: where it runs (this chat, Claude agent, or other subscription when helpers are on), its level, then the model and thinking. Click ▸ on a row for the details: tokens, where its model came from, the verdict's reason.
  3. 3Rerun one rung up. A finished step that came back weak can be redone on the next stronger rung. Claude is asked to run it again.
  4. 4Cost line. The ⇄ button cycles three spans: This plan, This chat and All time. It shows what the main chat cost, what the subagents cost, and what was saved. Details ▸ opens the tiles and tables. A cost shown as "?" means a model with no price (see Models and prices).
  5. 5Settings and report. Settings ▸ replaces the plan until you press Done. Write report is for asking someone for help.

In the terminal

  • Give the pane the keys: press ctrl+x then Tab, or click it.
  • ↑ ↓ scroll. Esc returns to the prompt.
  • A short choice (up to three options) is a button marked ⇄: press Enter to go to the next option.
  • A longer choice (models, effort, Spend) is a button marked ▾: Enter opens a list under it, ↑ ↓ or Tab move, Enter picks. The current one has ●.

In the desktop app

  • Type /router, or turn on Open the pane in new chats.
  • Scroll with the mouse or trackpad.
  • Click ▸ to open a step, click a picker to change it, click a button to press it.

5. The settings most people touch

Press Settings ▸ in the pane. The top five rows (the Basics) are the ones most people ever change. A small • marks any value that differs from the default.

  • Ask me before a plan runsOn by default: you see the three-answer question. Turn it off if you trust the plans and want them to run at once.
  • Plan every messageOff by default. When on, every message you type carries a reminder to plan before using tools, even for one-step tasks. Turn it on if you want the router in every request.
  • SpendThe models and thinking the three levels run on. Thrifty: haiku low, sonnet low, opus medium (light, standard, deep). Balanced (default): haiku low, sonnet medium, opus high. Best quality: haiku high, sonnet high, opus high. Custom appears when you set the levels by hand under Models per level.
  • Open the pane in new chatsSaves typing /router every time.
  • Other subscriptionsOff / Long steps / All steps. Only for helpers. Leave it Off unless you have set them up.

Below the basics are closed groups (Models per level, Other subscriptions, Learning, Models and prices, Skills, Diagnostics, Advanced). Each closed group says in one line what is inside. Nothing there needs touching to get value from the router. Your settings are remembered across chats and are kept in ~/.config/model-router/settings.json, so they come back after a reinstall.

6. Going further: the advanced features

Each card works on its own. Open only the ones you want. They all follow the same shape: what it is, whether you need it, what it needs, how to turn it on, how to check it, how to turn it off.

Verdicts, advice and ApplyHow the router learns which model each kind of work needs

What it is

Each step Claude delegates gets a kind (a short label such as summarize or code-review), and when it finishes Claude gives it a verdict: ok (used as returned or with small edits), weak (needed a rerun or had a real error), overkill (plainly mechanical work that ran higher than it needed), or cut short (stopped by something outside the model, such as a lost connection or quota; it says nothing about the model). From these the pane suggests changes, called advice, each with an Apply button.

Do you need it?

It runs by itself. It pays off if you use the router for the same kinds of work again and again.

What you need

Nothing to install. Advice appears once a kind has at least 3 runs on the rung it uses now.

Turn it on

  1. Use the router for a while. Under the cost line the pane says History: 12 runs; advice needs 3 on one rung.
  2. When advice appears under the cost line it shows its evidence, for example "code-review on light: 3 of 4 weak". It suggests one rung up when at least half of the runs were weak, or one rung down when at least half were overkill and none of the last three was weak.
  3. Press Apply to accept. For a kind this sets that kind's default model (Settings → Learning). For runs with no kind it changes that level's model and thinking.

Check it works

After Apply, open Settings → Learning: the closed line says how many kinds are tuned (for example auto off · 2 kinds tuned).

Turn it off

Nothing changes unless you press Apply, so just do not press it. To undo one, Settings → Learning → the kind → reset. To start over, Settings → Advanced → Clear history; it asks you to confirm. A run wrongly marked weak because of a lost connection can be fixed with the quiet cut short? link on its card (undo puts the old verdict back).

Auto mode, and trying a cheaper rung needs 0.29.4Let the router pick the model for each kind from its own history

What it is

Auto mode sends a kind of step to the cheapest rung that has worked well for it before: by default, at least 90% ok over at least 5 runs on that rung. Your own picks on a step still win. Try a cheaper rung now and then is a second switch, off by default: auto mode alone only chooses among rungs it has seen, so a kind that always ran on Sonnet never finds out that Haiku would do. With this on, after every 4 runs on the learned rung, the next run of that kind tries one rung down. If the try was weak (or you reran it), the router stops trying that rung. If it works enough times, it becomes the new learned rung.

Do you need it?

Only if you plan many steps of the same kinds and want the router to tune itself. Auto mode changes routing without asking, so wait until the advice has proved right a few times. The cheaper-rung switch is an experiment that spends a few runs to learn; leave it off if you would rather not risk a weaker answer now and then.

What you need

Some history with verdicts (see the card above). The cheaper-rung switch needs model-router 0.29.4 or later and works for Claude agent steps only.

Turn it on

  1. Press Settings ▸, then open the group Learning.
  2. Switch on Auto mode.
  3. Optional: switch on Try a cheaper rung now and then.
  4. Optional: under "Auto picks a rung with at least", choose how many runs (3, 5, 8, 10 or 20) and what share must be ok (70, 80, 90, 95 or 100%).

Check it works

The group's closed line reads auto on · …. A step's details (▸) say where its model came from, for example "auto: sonnet · high (learned, 5 runs)". A try says "auto: trying haiku · high, one rung below what it learned".

Turn it off

Switch the same two switches off in Settings → Learning. Steps go back to the kind's default, then the level's.

Helpers: run steps on your other subscriptionsKiro, GitHub Copilot, Antigravity, Codex, another Claude account

What it is

Normally each step runs as a Claude subagent. With helpers, a step can instead run on another subscription you already pay for: Kiro, GitHub Copilot, Antigravity (its command is agy), Codex, or a second Claude account (for example a university plan, which is a second CLAUDE_CONFIG_DIR). Your main chat starts the helper, reads its report and checks it. The cost line then adds Moved off Claude: … showing what each provider used.

Do you need it?

Only if you have one of those subscriptions and want long, self-contained work (research, code to a spec, sweeps) to use their quota instead of Claude's. Most people do not, and the router works fully without it.

What you need

  • The herdr-delegate plugin from this marketplace: 
    /plugin install herdr-delegate --marketplace Horef/claude-plugins
  • At least one helper tool installed on your computer and logged in: Kiro (kiro-cli), GitHub Copilot, Codex, Antigravity (agy), or another Claude account. A second Claude account is found by itself once it has been used on this machine. Open each tool once by hand and sign in, so it does not stop at a login screen later.
  • Python 3 (the router runs herdr-delegate's script with python3).
  • One of these two ways of running them:
    • Herdr terminals: Herdr's hc command on your PATH, with Claude Code started from a Herdr terminal (Herdr is a terminal app that keeps helper terminals alive). Each helper runs in a terminal you can watch and type into.
    • Direct mode (no Herdr): needs herdr-delegate 0.15 or later. Each helper runs once, on its own, in the background. Compared with Herdr: no live screen, no approvals while it runs (anything outside its allowed list is refused and reported as blocked), no questions, and a run stops after 60 minutes by default.

Turn it on

  1. Install herdr-delegate and your helper tool(s) as above, then type /reload-plugins.
  2. Press Settings ▸. Under the basics, set Other subscriptions to Long steps (only long self-contained steps go to helpers) or All steps (every self-contained step that would be a subagent step). This costs the chat one prompt-cache refresh.
  3. Open the group Other subscriptions to see the order each level tries its helpers in (for example deep: kiro → copilot → agy) and to change it with Edit. Run helpers chooses Herdr, else direct (the default), Herdr only or direct only.

Check it works

The health line says what you have: ✓ Router on · helpers: Herdr (Kiro, Copilot, Antigravity) or ✓ Router on · helpers: direct mode (no Herdr terminal). If something is missing it says ✗ Helpers can't run: … and names the first problem, for example this chat is not inside a Herdr terminal. Press Why ▸ next to it: it lists every check with a one-line fix. Fix the first ✗, press Look again in Settings → Other subscriptions, and read the line again. The status line adds helpers ✗ while it is broken.

Turn it off

Settings → Other subscriptions → Off. Any helper step in a plan then runs as a subagent. The router runs no commands of its own while helpers are off.

Also in the Other subscriptions group: Helper models (which model and thinking each helper uses; Check models asks each tool what it offers) and Copilot Fusion (off by default). Full reference: the README's Helpers section.

The New models cardWhen a new model appears, and what to do about it

What it is

The router notices when a model is new (or gone). With helpers on it reads each installed tool's model list at the start of a chat, and it also notices a new Claude model the first time it appears in your usage. It then asks Claude, once and when your task is finished, to look the model up and write notes (release, strengths, weaknesses, which level it suits). A New models card appears under the health line, only while something is waiting. Each proposal reads like deep Antigravity: gemini-4-neon high → … with Apply and Dismiss buttons.

Do you need it?

Useful if you use helpers and want to try new models without hunting for them. If you use only Claude, you will rarely see it.

What you need

Nothing extra for Claude models. For helper models, helpers must be ready.

Turn it on

  1. It is on by itself. To look now, open Settings → Models and prices and press Check now.
  2. When the card shows a line, press Notes ▸ to read why it is proposed.
  3. Press Apply to make the change (it sets that level's model), or Dismiss to remember that you said no.

Check it works

After Apply the line says applied in place. Settings → Models and prices shows Model notes (N) · checked <date>.

Turn it off

Nothing changes without your click, so there is no switch: press Dismiss on a proposal and it is not shown again.

The Herdr sidebar (Herdr users)The plan in a normal, scrollable column beside your terminals

What it is

If you run Claude Code inside the Herdr app, a small Herdr mod shows the router's plan in a column on the right: health line, plan rows and cost. It is read-only: approving, editing and Settings stay in Claude Code. It helps because the pane cannot scroll while the approval question is open in a terminal.

Do you need it?

Only if you use Herdr on a Mac and your plans are long.

What you need

The Herdr app (a ~/.config/herdr-app folder), Python 3, and model-router installed.

Turn it on

  1. Run the setup script once, using the newest version folder: 
    python3 ~/.claude/plugins/cache/horef-claude-plugins/model-router/<version>/herdr/sidebar.py
  2. It adds a column to a personal copy of Herdr's layout and switches to it. Run it again after a plugin update that changes the herdr/ folder.
  3. Press ⌘⇧R to show or hide the column.

Check it works

The column shows the focused chat's plan. With no recent chat it says No router state yet. Start a chat with the router and send a plan.

Turn it off

Press ⌘⇧L to go back to Herdr's own layout. To stop the router writing the data it reads, switch off Settings → Diagnostics → Show in Herdr.

Write reportA file you can send when you ask someone for help

What it is

A single text file with the router's version, your computer and surface, the settings that differ from the defaults, the health checks with fixes, the helper setup, some counts, and the last 100 log events. The log never holds your prompts, briefs, file contents or step titles.

Do you need it?

When something is wrong and you are asking Sergiy (or anyone) for help.

What you need

Nothing. The log that feeds it is on by default and kept for 14 days.

Turn it on

  1. Type /router report. Or press Write report in the pane's footer, or under the health line's Why ▸.
  2. The pane says where the file went: ~/.config/model-router/report-YYYYMMDD-HHMM.md. Send that file.

Check it works

The pane shows Report written: … next to the button. Open the file to see what it holds before you send it.

Turn it off

Nothing is written unless you ask. To stop the log too, switch off Settings → Diagnostics → Keep a log.

Reruns and edits after approvalFix one step without redoing the plan

What it is

Two pane tools for a plan that is running or done. Rerun one rung up redoes a finished step on the next stronger model. Editing a running plan: change a step's where, level, model or thinking in the pane. The change is held as a draft (marked ✎) until you press Send changes (N) at the top of the plan, so a half-finished edit never reaches Claude. Discard drops it.

Do you need it?

When a result is not good enough, or you want a later step on a stronger model.

What you need

Nothing.

Turn it on

  1. Rerun: on a finished step, press ↑ Rerun on …. Claude is asked to delegate it again. A rerun counts as weak in the router's learning.
  2. Edit: change a picker on a step that has not started, then press Send changes (N). Claude hears about it at its next turn.

Check it works

The row says change noted, applies from the next turn until Claude's next turn, and then runs with your values.

Turn it off

Do not press them. Discard removes an unsent edit. Clear plan (at the end of the plan) empties the pane's plan.

Models and pricesWhat the router assumes things cost, and what "?" means

What it is

The router's cost and savings figures are estimates from list prices and the token counts the API reports. Settings → Models and prices lists every model it knows, with its price per million tokens. A model with no price shows its cost as "?" and is left out of the savings.

Do you need it?

When you see "?" in the cost line, or you use a model the router did not know.

What you need

The price from the model's provider: "input output" in dollars per million tokens, or all four numbers (input, output, cache write, cache read).

Turn it on

  1. Settings → Models and prices.
  2. Find the model and type its price. You can also add a model by name.

Check it works

The "?" in the cost line turns into an amount on the next response.

Turn it off

Clear the price box to go back to the default (or none).

Groups, parts and Always planBigger plans, and planning every message

What it is

Claude can split a step into parts that need different levels or run side by side. A step with parts is a group: it is done when all its parts are, and its cost is the sum. A part can also be several identical agents at once (shown as ×N). The parts sit indented under their group, each with its own pickers. Always plan is the setting Plan every message (see Settings above).

Do you need it?

You do nothing for groups; Claude builds them when the work splits naturally. Turn on Plan every message if you want a plan even for small tasks.

What you need

Nothing.

Turn it on

  1. Groups appear in plans by themselves.
  2. For Always plan: Settings → Plan every message.

Check it works

A group's second line reads rated deep · 2/3 done · ≈$x. With Plan every message on, the status line adds · always plan.

Turn it off

Switch Plan every message off in Settings. Groups cannot be switched off; they only appear when the work is split.

7. Keeping it updated

Mods do not update by themselves unless you switch that on. There are two ways. You only need one.

  1. Turn on auto-update for the marketplace (once). In a chat, run /plugin, open the Marketplaces tab, pick horef-claude-plugins and turn auto-update on. After that Claude Code refreshes it at the start of each session.
  2. Or update when the mod tells you. When a newer version exists the mod shows an Update notice. The Update button fills the chat box with a request for Claude to run the update for you, and you press Enter. You can also type /router update to check now.

Either way, finish with /reload-plugins in chats that are already open. If you use more than one Claude account, each account updates on its own. Full steps: Updating.

8. Troubleshooting

Nothing happens when I send a message
The router only plans requests with several steps. Try the starter prompt, or turn on Plan every message in Settings. Check that the line under your prompt starts with ⇄ Router on.
The pane does not show
Type /router. If the command is unknown, the mod is not loaded: type /reload-plugins, or run claude plugin list in a terminal and look for model-router. In a terminal, press ctrl+x then Tab to scroll it. Turn on Open the pane in new chats to have it ready.
The health line shows ✗ Helpers can't run
Helpers are optional. Press Why ▸ and follow the first fix, then Look again in Settings. Or switch Other subscriptions to Off. See Helpers.
Costs show "?"
That model has no price. Add one under Models and prices.
Claude ignores the plan, or the rules did not arrive
Ask Claude: "Call the model-router plan tool with status: true and show me the result." It reports the version, whether the rules are in this chat, and the health checks.
Something else is wrong
Type /router report and send the file it writes. See Write report.

To remove the router, type /plugin uninstall model-router. Plans stop appearing; nothing else changes in your chats.
