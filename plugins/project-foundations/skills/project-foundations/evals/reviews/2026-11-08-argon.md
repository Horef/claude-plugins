### A4 [should] `[tool.docmap.facts]` glob form: `references/docmap-config.md` contradicts `glob_facts()` implementation, and multi-file globs collide on `Fact` names and cannot read nested keys

- **Evidence:**
  1. **Doc vs. code contradiction:** `references/docmap-config.md:43` states:
     *“`files` is a glob (pathlib syntax: `*` stays within a folder, `**` recurses; it reads files on disk, so keep them tracked)”*.
     In `scripts/docmap.py:396`, `glob_facts` actually runs:
     `paths = sorted(f for f in tracked_files() if matches(f, [spec["files"]]))`
     which uses `tracked_files()` (not disk globbing) and `fnmatch.fnmatch` (where `*` **crosses `/`**, as line 3 of `docmap-config.md` states!). For example, `files = "configs/*_weights_*.json"` in `simple_complex_v1` also matches `configs/archive/2026-10/generators/mouse_cluster_weights_v1.json`.
  2. **Duplicate `Fact` column across versioned files:** In `scripts/docmap.py:430`, `build_facts()` formats every glob row's first column as `f"| {name}{': ' + k if k else ''} |"` without the file stem. In `simple_complex_v1` (O16), `mel1998_option_h_weights_v1.json` and `mel1998_option_h_weights_v2.json` both define `a_h1`, `a_h2`, `a_h3`, `a_h3_native` (and `h5t_v1`/`h5t_v2` both define `a_h5t`, `b_h5t`, `c_h5t`). Even in `evals/run.py:144,146`, the generated table has two rows with the **identical** `Fact` label `| calibrated weights: a_h3_native |`, making "cite `FACTS.md` by fact name" ambiguous whenever two matched files share a key.
  3. **Top-level keys only:** `glob_facts()` (`scripts/docmap.py:414`) only iterates top-level dict keys (`for k in sorted(data)`). Almost all TOML files and encoder/candidate JSON files in `simple_complex_v1` (`configs/encoders/*.json`, `configs/candidates/*.json`) nest their parameters (`spatial.center_sigma_deg`, `morphology.profile`). Passing a nested file to `glob_facts` dumps raw JSON dicts into the `Value` column (`{"center_sigma_deg": 1.42, ...}`).
  4. **Unhandled crash in `fact_value()`:** `glob_facts()` catches `ValueError` on corrupt JSON/TOML (`scripts/docmap.py:411`), but `fact_value()` (`scripts/docmap.py:380-384`) does not, crashing `update`/`check` with a traceback.
- **Proposed change:**
  1. Fix `references/docmap-config.md:43` to match the code: `files` matches `tracked_files()` using `docmap`'s glob rules (`*` also matches `/`; use `configs/generators/*_weights_*.json` so `configs/archive/` is not matched).
  2. When a key `k` appears in more than one matched file in `glob_facts(spec)`, include the file stem in the `Fact` label (`calibrated weights (v2_weights_1): a_h3_native`), or always support an optional `key = "dotted.path"` in `glob_facts` (one row per file: `<name>: <file stem>`).
  3. Catch `ValueError` in `fact_value()` and strip newlines from values in both `fact_value()` and `glob_facts()`.

### B2 [should] Non-Python code files with `/* ... */` or `/** ... */` headers fail `docmap.py check`, and `code_dirs` forces code tables onto prose parent folders

- **Evidence:**
  1. **JSDoc / C / CSS block comments fail (`LEARNINGS.md` O5):** `file_summary()` (`scripts/docmap.py:228-235`) matches only single-line comment prefixes `r"^(#|//|--|%|;)\s*(.+)"`. In TypeScript, JS, Java, C, C++, and Rust, files starting with a standard JSDoc/Doxygen block comment (`/** Summary. */` or `/**\n * Summary.\n */`) return `""` and fail `docmap.py check` with `error: <file>: no header comment`.
  2. **Ancestor pollution in `code_dirs()` (`LEARNINGS.md` O4 & `simple_complex_v1/docs/MAP.md:23-26`):** `code_dirs()` (`scripts/docmap.py:267-275`) walks `while str(d) not in ("", "."): dirs.add(str(d)); d = d.parent`. When a helper put a single script `docs/literature/gosi_threshold/calc/gosi_vs_osi.py` in `simple_complex_v1`, `code_dirs()` turned `docs/literature/gosi_threshold/`, `docs/literature/`, and `docs/` into "code folders", forcing `README.md` stubs and `| Entry | What it is | Imported by |` tables into prose folders (and in `claude-plugins`, forcing `readme_exempt` on `plugins/`, `plugins/*/skills/`, etc.).
- **Proposed change:**
  1. In `file_summary()` (`scripts/docmap.py:228-235`), also match `/*` / `/**` comments (taking the text after `/*`/`/**` or on the next `* ...` line), and make the `check` error say `no header comment (first line: //, #, /* or --)`. (Resolves O5.)
  2. In `code_dirs()` (`scripts/docmap.py:267-275`), add only directories that *directly* contain a code file (`d = Path(f).parent; if str(d) not in ("", "."): dirs.add(str(d))`), instead of walking every ancestor up to the root. (Resolves O4 and prevents prose folders like `docs/literature/` from becoming code directories when a subfolder has a helper script.)
