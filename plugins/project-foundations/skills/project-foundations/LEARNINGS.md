# Learnings: project-foundations

Observations from use, written by the agents that used this skill; the strange-loop skill turns them into changes.
One line each: `- O<n> <date> [<kind>] <section>: <what happened, what would have helped> (<harness>, <context>)`.
Kinds: failure, friction, misled, missing, workaround, win, wish. ` ×N` = seen N times; ` → <version>` = resolved there.

## Open
- O4 2026-10-30 [friction] Step 4 / docmap check: in a plugin marketplace repo (Horef/claude-plugins) the one-README-per-code-folder rule asks for READMEs in `plugins/`, `plugins/x/skills/`, `scripts/`, `evals/`; needed `readme_exempt` globs. A documented preset for skill/plugin repos would help (claude-code-web, setting up the genome)
- O5 2026-10-30 [friction] docmap check: TypeScript files whose first line is an import fail "no header comment"; existing mods (model-router) needed `docstring_exempt`. Fine as a rule, but the error could say what a header comment looks like for TS (claude-code-web, setting up the genome)
- O6 2026-10-30 [wish] Step 6 Audit: nothing measures whether AGENTS.md helps; research (Gloaguen et al. 2026, "Evaluating AGENTS.md") found LLM-written context files can lower success and raise cost. An audit step that tries one task with and without a doubtful rule would ground pruning in evidence (claude-code-web, research for strange-loop)
- O13 2026-11-08 [failure] Step 4.1 / docmap link check: scripts/docmap.py 5.7.0 still treats only ^[a-z]+: as a URI scheme, so x-devonthink-item: links (hyphenated scheme) are reported as broken relative links; 769001 patched its copy to RFC 3986 ^[A-Za-z][A-Za-z0-9+.-]*: (both regexes, lines ~573 and ~691) at 5.6.0 and had to re-apply it after upgrading to 5.7.0. Carry the fix into the skill. (claude-code, 769001)
- O14 2026-11-08 [friction] STATUS.md: with several research directions the snapshot became one long bullet per direction (some ~300 words); scanning for 'what is open' takes reading paragraphs. Would help: a short Directions table (one line each: name, folder, state, next) above the prose, with detail in the direction's own folder. (simple_complex_v1)
- O15 2026-11-08 [friction] Id namespaces collide across the scaffolding: write-up analyses A1-A6, research-assistant A1, wirings H3/H5t, hypotheses H1-H4, ledger rows L1.. that mean different papers in each docs/literature/<topic>/. research-assistant now tags its ids (NB-H1); literature ledgers and write-up review analyses still use bare ids. Would help: a project-wide rule that every id family outside DECISIONS/RESULTS carries its folder's tag, and a docmap check for bare ids cited across folders. (simple_complex_v1)
- O16 2026-11-08 [missing] Calibrated parameters (here synaptic weights per wiring, draw and NMDA ratio) are spread over many generator JSON files (option_h_weights_v2, a2_a6_weights_v1, h5t_v1, nmda_bracket_weights_v1); finding the current H3 native weight needed knowing the file. Would help: FACTS.md-style generated index of calibrated values from configured files ([tool.docmap.facts] glob over weights files). (simple_complex_v1)

## Resolved

From reading, not use: confirm before restructuring (claude-code-web, adopting into the genome) → 5.8.0
- O12 2026-11-06 [friction] docmap stats/check/rotate: stats prints 'Read whole at session start (warning above read_max_tokens = 8000)' with a total of 8487, yet check stays silent because the budget is per file (tools/docmap.py:626), and 'rotate' is a no-op when every WORKLOG entry is from the current month, so the owner's request to rotate the 2.5k-token WORKLOG changed nothing and there was no sanctioned way to shrink it. Would help: a total budget (or a stats wording that says per file), and a rotate option to move older entries of the current month (e.g. --keep N). Related to resolved O7 (copilot-cli, Alloy) → 5.7.0

In simple_complex_v1 a GUI built around the stimulus fields of the day hid a new kind of difference (PV/SST inhibition in the condition's model), and the owner asked (2026-11-04) for the 'what will vary next?' question to be generalised to every domain (configs, schemas, formats, function signatures, reports, figures). (claude-code, simple_complex_v1) → 5.6.0
- O10 2026-11-01 [friction] WORKLOG/STATUS maintenance: every unit of work needs a new dated entry inserted at the top of WORKLOG.md (below the header, above the newest entry) and STATUS lines updated; the agent wrote a throwaway Python snippet for the insertion six times in one session. Would help: 'docmap worklog add TITLE [--body FILE|-]' that inserts a dated entry in the right place (and rotates on a month change), plus a STATUS 'Updated' date bump (claude-code, simple_complex_v1, 1 Nov 2026) → 5.4.0
- O9 2026-11-01 [friction] docmap update / generated blocks: parallel git worktrees (four helper agents, one branch each) all conflict on docs/MAP.md and the generated tables in folder READMEs when they run update; the lead had to tell helpers not to run update and regenerate once after merging. Would help: a documented merge workflow plus a merge driver or 'docmap update --after-merge' that resolves conflicts in generated blocks by regenerating them (claude-code, simple_complex_v1, GUI phases 3-6 in worktrees, 1 Nov 2026) → 5.4.0
