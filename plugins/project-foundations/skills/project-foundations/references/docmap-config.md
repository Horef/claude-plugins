# docmap configuration reference

Every key `tools/docmap.py` reads from `[tool.docmap]` in `pyproject.toml` (or the top level of `docmap.toml`). Defaults are in `DEFAULTS` at the top of the script. In globs, `*` also matches `/`.

```toml
[tool.docmap]
exclude = ["references/*"]            # never mapped (vendored copies, large reference material)
readme_exempt = []                    # folders that need no README
docstring_exempt = []                 # files that need no header doc
link_exempt = ["docs/archive/*"]      # markdown whose relative links are historical
lifecycle = ["docs/*.md"]             # docs that must open with a Status line (generated/append-only logs are exempt)
lifecycle_exempt = []                 # e.g. ["docs/briefs/*"] if briefs are throwaway
lifecycle_strict = false              # true: missing/stale Status lines fail CI (switch on once every doc has one)
verify_max_days = 60                  # a "current" doc older than this is due for re-verification
proposal_max_days = 30                # an open proposal older than this: decided? supersede it
archive_dir = "docs/archive"          # where `docmap.py archive` moves retired docs (same layout as under docs/)
archive_no_rewrite = ["*.json", "*.jsonl", "*.yaml", "*.yml", "*.toml", "*.csv", "*.tsv", "*.ipynb", "*.xml", "*.ini", "*.cfg", "*.lock"]   # archive lists path mentions here, never rewrites them (content hashes); setting the key replaces this list, so repeat the defaults when adding one
archive_keep = ["docs/writeups/*/review/**", "docs/research/**", "docs/literature/**"]   # records of a live folder: never moved,
                                      # never due for re-verification, counted apart in `docs`
archive_grace_days = 7                # lifecycle_strict: retired docs left in live folders fail check this long after retiring
                                      # (dated from git history: CI needs `fetch-depth: 0`; a shallow clone makes every doc look recent)
map_files_max = 150                   # MAP.md lists files up to this many code files; beyond, folders only
read_max_tokens = 8000                # warn when a file agents read whole (AGENTS, STATUS, WORKLOG, MAP) is bigger
read_total_max_tokens = 12000         # warn when those files together are bigger (the cost of a session start)
worklog_max_tokens = 6000             # `worklog` rotates the oldest entries above this (default: min(read_max_tokens, read_total_max_tokens // 2))
status_line_max_words = 80            # warn when a bullet or paragraph line in STATUS is longer: one short line per workstream, detail in its folder
id_scan_exempt = ["docs/archive/*", "docs/worklog/*", "docs/WORKLOG.md", "backlog/*"]   # markdown where ids are neither defined nor checked for bare citations
id_missing_exempt = []                # markdown whose citations are not checked against the index ("cites D57, which is not in DECISIONS.md"): legacy docs citing another ledger's D ids
id_cite_exempt = []                   # ids that may be cited bare anywhere: exact ids or regexes that match a whole id, e.g. ["L\\d", "A1"],
                                      # or domain words that look like ledger ids: ["F[0-2]"] for harmonics (F1, F2), ["L[1-6]"] for cortical layers
number_prefix_check = true            # warn when two files in a folder share a numeric prefix (44_foo.py, 44_bar.sh)
number_prefix_exempt = []             # folders (globs) skipped by the numeric-prefix check

[tool.docmap.facts]                   # generated docs/FACTS.md: one row per key value, read from its source
"default cell" = { file = "configs/cell.json", key = "id", note = "D27" }      # key = dotted path in JSON/TOML
"encoder preset" = { file = "src/mypkg/defaults.py", pattern = "^ENCODER = \"(.+)\"" }  # or a regex with one group
"calibrated weights" = { files = "configs/generators/*_weights_*.json", keys = "^[abc]_h3_" }  # a glob: one row per (file, top-level key)
"morphology" = { files = "configs/enc/*.json", key = "spatial.sigma" }          # a glob + a dotted key: one row per file

[[tool.docmap.forbid]]                # one block per architectural rule
source = "mypkg"
except = ["mypkg.adapters"]           # where the import is allowed
imports = ["torch", "neuron"]
reason = "core runs without heavy backends"

[tool.docmap.runs]                    # research projects: run index from run manifests (JSON)
manifests = "outputs/**/manifest.json"
out = "docs/RUNS.md"
columns = { run = "run_id", created = "created_utc", commit = "project_git.revision", config = "config_hash" }
# columns map a header to a dotted key in the manifest; the second column is the sort key (use the date)
# Also available (see DEFAULTS in the script): agents_max_lines (default 150), indexes (heading patterns for the ID
# indexes), portable / portable_exempt (files scanned for machine-specific paths), portable_allow (paths that are facts
# about other code, e.g. an upstream's hard-coded "/home/someone"), local / local_example (file names),
# worktree_stale_days (default 1: a merged worktree idle longer than this fails check)
# An index with `ids` (e.g. {file = "docs/ANALYSES.md", pattern = '^## (A\d+) — (.+)$', ids = '\bA[1-9]\d*\b'}) makes
# `get A2` print that entry, `ids` list its family, and `check` verify citations and superseded status for it
```

Facts from many files: `files` is a glob over the tracked JSON or TOML files, matched with `fnmatch` like every other glob in docmap (`*` also crosses `/`, so `configs/*.json` includes subfolders). With the optional `keys` (a regex, `re.search`) each matching top-level key is one row, named `<fact name>: <key>`; a key that occurs in several files is named `<fact name>: <key> (<file stem>)` so every label is unique. With the optional `key` (a dotted path, as for a single file) each file is one row named `<fact name>: <file stem>`. Rows are sorted by file, then key. Use `file` + `key` (or `pattern`) for one value; the forms can be mixed in one table. A glob that matches nothing shows a `NO FILES MATCH` row, a file that cannot be parsed shows `UNPARSEABLE FILE`, a missing `key` shows `MISSING KEY`, and values are flattened to one line.

Ids: `check` finds the id families a doc defines (`A1`, `H3`, `NB-H1`): as `##`-`####` headings (`## A1: T`, `## A1. T`, `## A1 - T`, also with an en or em dash), as the `pattern` matches of a configured index (whatever it numbers), as line-start bullets (`- A1.`, `- A1:`) or in the first column of a table headed `id`. A family counts in a file only with at least two ids defined there, or its `<family>1`. An id defined in two or more folders (a folder under `docs/<group>/<slug>/` is one scope; otherwise the file's folder) is ambiguous, and `check` warns, once per citing file and family, about every file that cites such an id bare. It does not warn when the citing file is in one of the defining scopes, when the line names one defining scope's slug, when the id matches `id_cite_exempt`, or when the file matches `id_scan_exempt` or is superseded or historical; tagged ids (`NB-A1`), ranges like `L2/3`, code spans, URLs, generated blocks, code fences and HTML comments are not citations. Tag folder-local ids with the folder's short tag. `check` prints one warning per family (`F ids cited bare in 15 files (e.g. ...)`); `python tools/docmap.py ids` lists the families, where each is defined, the ambiguous ones first, and who cites them bare, and `ids F` every bare citation of family F as file:line. The folder slug counts on the raw line, so `` `docs/writeups/x/` `` in backticks names the folder.

Cited ids must exist: `check` warns "cites D57, which is not in docs/DECISIONS.md" for every doc that cites an index's id (default `D<n>`) the index does not define. `id_scan_exempt` and `id_cite_exempt` do not cover this check (they cover the ambiguity check above); `id_missing_exempt` does, by glob (e.g. `["docs/reports/*"]`). Prefer fixing the cause when a repo's old docs use bare `D<n>` ids of another ledger: give the new ledger a free prefix through `indexes` (`pattern = "^## (TD\\d+)\\.\\s*(.+)$"`, `ids = "\\bTD\\d+\\b"`) so the old ids are never read as citations of it.

Moved modules: a file whose only job is `sys.modules[__name__] = importlib.import_module('pkg.sub.mod')` (a literal argument, usually the `else:` of an `if __name__ == '__main__': runpy.run_module(...)`) is a forwarding stub. docmap reads it from the syntax and counts an import of the stub as an import of `pkg.sub.mod`: `show`, `uses`, `where`, `deps`, `calls`, the folder tables and the MAP follow the move, importer lists say "(via stub old.py)", and `show old.py` names the real file. A computed argument is not recognised.

Retiring docs: `docmap.py archive` lists (dry run) every lifecycle doc whose Status is `historical` or `superseded ...` outside `archive_dir` and `archive_keep`, with its destination `archive_dir/<path under docs/>` and its companions: same-stem rendered copies beside a retired `X.md` (`.pdf`, `.png`, `.svg`, `.jpg`, `.jpeg`, `.webp`, `.html`, `.docx`, `.pptx`; never code, data or another doc, nothing under `archive_keep`); on a name collision the name gets `-YYYY-MM` (never overwritten). `archive --apply` moves them (`git mv`; a plain move if untracked), rewrites relative Markdown links in live docs and in the moved docs, rewrites every exact path mention of a moved file in the live text files (Markdown, code, shell scripts, docstrings; not data and config files matching `archive_no_rewrite`, default JSON, YAML, TOML, CSV, TSV, notebooks, XML, INI, CFG and lock files, whose mentions are listed apart because they may carry content hashes such as run ids or model identities): the repo-relative path (`docs/X.md`, `./docs/X.md`; a moved folder `docs/briefs/` as a prefix) or a relative path that resolves from the file's folder to the moved file (`../X.md`, `./X.md`), in the same prefix style, matched on path boundaries (`docs/X.md.bak`, `olddocs/X.md`, `HEAD:docs/X.md` and `host:docs/X.md` are not hits), and writes the rows of `archive_dir/README.md` (file, original path, date moved, Status line; existing rows keep their path and date). It reports five things (the data and config line only when there are such mentions): rewrites in Markdown (count), rewrites in code and scripts (file:line: run the tests), mentions left to decide by hand (`not rewritten: bare names, code examples, ref:path`, file:line), every mention in a data or config file (`archive_no_rewrite`, matched case-insensitively; path, relative path or bare name, also under `--no-rewrite-paths`; file:line, edited by hand only when no hash or run id depends on it), and the mentions in the append-only logs (the configured indexes such as DECISIONS and RESULTS, the run index, the WORKLOG and its months), which are history and are only counted. The dry run reports the same counts. Generated blocks, the archive, retired docs and anything that is not a text file (UTF-8, no NUL byte, at most 1 MB: one test for the rewrite and the list, whatever the extension) are not touched. In Markdown, fenced code blocks and inline code holding link syntax are examples: not rewritten, listed to decide by hand (a plain inline-code path such as `` `docs/X.md` `` is rewritten). `--dir` and `--legacy` take POSIX or Windows paths; `--dir` refuses `archive_dir`, a folder inside it or one of its parents, and a `--dir` inside another one moves with it. Everything under `archive_dir` is history: no README, header, link or MAP checks there. `--no-rewrite-paths` rewrites links only and lists the path mentions instead. `--dir PATH` retires a whole folder; `--legacy GLOB` also takes files matching GLOB that have no Status line (or a retired one, even under `lifecycle_exempt`). It never runs on its own (not in `update`, no hook). A finished plan is retired as `historical (done YYYY-MM-DD; results <ids>)`. `docmap.py docs` lists only live docs outside `archive_keep` (`--all`: every doc).

Budgets: `read_max_tokens` applies to each file agents read whole at session start; `read_total_max_tokens` to the sum of all of them. `check` warns on either, `stats` shows both. To shrink a WORKLOG that is over budget although every entry is from the current month: `python tools/docmap.py rotate --keep N` keeps the newest N entries and moves the rest to `docs/worklog/YYYY-MM.md` (plain `rotate` moves only earlier months). `worklog` does both by itself (earlier months; the oldest entries above `worklog_max_tokens`), but only in the main worktree on the default branch, since rotating writes two files and doubles merge conflicts between parallel branches; elsewhere, and with `--no-rotate`, it prints the `rotate` command to run after the merge.

Merges of generated files: after a merge or rebase with conflicts, `python tools/docmap.py merge-fix` resolves conflicts that lie only inside generated files or `docmap:begin..end` blocks by taking one side, regenerating with `update`, and `git add`ing them; conflicts in hand-written text are left untouched and listed. To prevent conflicts on whole generated files (`docs/MAP.md`, `docs/FACTS.md`, `docs/RUNS.md`) altogether, `python tools/docmap.py merge-driver --install` adds `merge=docmap` lines to `.gitattributes` (committed) and sets `git config merge.docmap.driver true` (per clone, so each clone runs `--install` once; keeps ours on merge, then a post-merge `update` regenerates).

## What `check` reports

`check` fails on: stale generated blocks, missing folder descriptions or file headers, files that don't parse, broken relative links in Markdown, forbidden imports, a linked worktree whose branch is merged and has sat idle longer than `worktree_stale_days` (`docmap.py worktrees --remove` removes the clean ones), and, under `lifecycle_strict`, retired docs left in live folders longer than `archive_grace_days` after their Status changed (date from git log). Warnings are printed by consequence: version drift, reading budgets, merged worktrees, lifecycle and STATUS, then ids. It warns on: a just-merged worktree, cited decision IDs that don't exist, AGENTS.md over the length limit, a file agents read whole at session start over `read_max_tokens`, or those files together over `read_total_max_tokens` (`docmap.py stats` shows the reading cost), old WORKLOG months, STATUS not touched for many commits, docs without a Status line, "current" docs not verified for `verify_max_days`, proposals open longer than `proposal_max_days` (records under `archive_keep` never fall due), retired docs in live folders (one line: `N retired docs in live folders`), a STATUS table whose rows have a different cell count than its header (one line per table), a STATUS `Works` row whose own date is older than `verify_max_days`, an In-flight row whose ISO expected end has passed (silent without an `## In flight` section), a STATUS bullet or Workstreams-table row longer than `status_line_max_words` (one short line per workstream; detail goes to its folder), bare ids (`A1`, `H3`) cited outside the places that define them when they are defined in several folders (not in the append-only logs, whose entries are history; one line per family; tag folder-local ids: `NB-H1`; `docmap.py ids <family>` lists them), and lines in live docs that cite a superseded decision without saying so (a decision is fully superseded when its status says `superseded by D<n>`: the `status:` field of its heading, or a `Status:` line; "partly superseded by D<n>: <part>" is partial and not reported; a line that itself says the cited id is superseded is skipped). A stale `docs/FACTS.md` (a source value changed) is an error like any stale generated block.
