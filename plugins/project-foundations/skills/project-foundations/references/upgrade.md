# Upgrade procedure (core docs exist, map layer missing)

For project-foundations' Upgrade mode, and for a project whose `tools/docmap.py` is older than the skill's (compare `DOCMAP_VERSION`; step 6b lists what each version added). Step numbers (Step 0-7, Step 4.1) are SKILL.md's.

Templates: `agents.md` (steps 3 and 6b), `agents-local.md` (3a), `folder-readme.md` and `file-headers.md` (step 2); `shims.md` when step 6 updates the Copilot fallback. Do not read the others: the core docs already exist.

1. Step 4.1–4.2: install and configure `tools/docmap.py`; turn the invariants already written in AGENTS.md/ARCHITECTURE (e.g. "core never imports heavy backends") into `forbid` rules, and check they pass. If a rule fails on a designed exception (e.g. an optional training package that exists to import torch), add it to `except` and record a decision; if it fails on a real violation, ask the owner.
2. `update`, then work through `check` errors folder by folder: README purpose paragraphs, module docstrings. Commit per folder.
3. Shrink `AGENTS.md`: move folder-specific rules into the folder READMEs (or a nested AGENTS.md if they must load automatically), add the "Finding your way" section and the new rows of the maintenance table, keep it under ~120 lines (`check` warns above 150).
3a. Make it shareable: create `AGENTS.local.example.md` and this machine's `AGENTS.local.md`; for every machine-specific path `check` reports (and every host name, user name or machine limit you find), move the value into `AGENTS.local.md` and refer to its key. Use `portable_allow` for paths that are facts about other code. Leave history (WORKLOG, RESULTS, archive) as it is.
4. Split a very long design document into per-component files if agents keep reading all of it; keep `ARCHITECTURE.md` short.
5. `rotate` the WORKLOG; set up `[tool.docmap.runs]` for research repos and run `runs`.
6. Add `python tools/docmap.py check` to CI; update the Copilot shim's fallback rules.
6a. Doc lifecycle: give every doc in `docs/` a Status line (read it against the code, DECISIONS and RESULTS first: current, proposal, superseded or historical; `docmap.py archive --apply` moves fully historical docs to `docs/archive/`). Mark superseded decisions in their status (`status: superseded by D<n>`; partly: `partly superseded by D<n>: <part>`). Configure `[tool.docmap.facts]` with the values docs keep repeating (defaults, presets, counts) and replace copied values with a reference to `docs/FACTS.md`. Keep `lifecycle_strict = false` until every doc has a Status line, then switch it on.
6b. Coming from an older `tools/docmap.py` (compare `DOCMAP_VERSION`): replace the script, then bring AGENTS.md's session-start and finding-your-way lines up to `templates/agents.md` (since 5.2: `find` and `get D<n>` instead of reading DECISIONS whole; since 5.3: the Scaffolding line under the title and the maintenance row that sends lessons about the scaffolding to the skill; since 5.6: the "Design for what will vary next" line under Conventions; since 5.9: the Workstreams table in STATUS (`templates/status.md`) and the new-line-of-work maintenance row, the "One id, one meaning" line under Conventions, and the `[module]` tags on the lines that belong to one module (keep a tagged line only when the project has that module, and drop the tag); since 5.10: the supersede-a-decision row, with its partial form; since 5.15: the worktree line under Git, removal as part of the merge; since 5.17: the list below), run `update`, and `stats` to see what a session now reads.
   Since 5.17 (coming from an older copy): `update` adds a Status column to generated folder tables of folders that hold docs and creates `docs/archive/README.md` (a generated table of the archive) when `docs/archive/` exists. Then:
   - Session start: bring "Start of every session" back to the template's list (status/pull, AGENTS.local, STATUS, the latest WORKLOG entry; everything else when the work touches it). List the project-specific additions (extra docs to read every session, old reviews, notes) for the person to keep or drop; never drop one silently.
   - Retired docs: `docmap.py archive` (dry run) lists the historical and superseded docs in live folders; show the list, then `archive --apply` (or schedule it): it rewrites links and exact path mentions, code and scripts included, so run the tests; decide the bare names it lists; `update`, `check`. Under `lifecycle_strict`, `check` fails on retired docs left in live folders longer than `archive_grace_days`, so do this in the upgrade. Records of live folders stay (`archive_keep`; set it if the project's records live elsewhere); old briefs without Status lines: `archive --legacy 'docs/briefs/*'`.
   - Ids: `check` now prints one line per id family; for domain tokens that collide with ledger ids (harmonics F1, F2; cortical layers L1-L6) add `id_cite_exempt` regexes (`["F[0-2]"]`) instead of retagging prose.
   - STATUS: fix the tables `check` reports (a stray `|` splits a cell); move finished workstreams to a "Done" line; re-check `Works` rows older than `verify_max_days`; with the compute module, add the In-flight table (`templates/status.md`) and the session-start line that checks it (`templates/agents.md`, `[compute]`).
   - Maintenance table: the finish-a-line-of-work row, the long-job row (`[compute]`) and the archive step in the milestone row (`templates/agents.md`).
7. Fix what `check` finds in old docs (broken links: fix the link or exempt truly historical folders via `link_exempt`; never delete history to silence a check).
8. WORKLOG entry with the before/after `check` summary; commit; push.
