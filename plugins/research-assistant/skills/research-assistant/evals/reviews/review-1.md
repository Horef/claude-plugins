## Ranked Findings (Most Important First)

### 1. [BUG / Q1, Q3] `ra.py gate G3` silently edits the HTML comment in `plan.md` instead of the real analysis section
- **Where:** `scripts/ra.py:116-127`, `templates/research/plan.md:5-21`, `evals/run.py:94`.
- **Problem:** `templates/research/plan.md:5-8` puts an example `## A1: <what it does, in a few words>\n- status: proposed` inside an HTML comment (`<!-- ... -->`) and instructs the agent: *"Copy the block below; keep the field names."* When an agent copies the block below the comment (preserving the comment, which `sections()` strips via `_strip_comments()`), `set_status()` (`scripts/ra.py:121-125`) checks `_strip_comments(s)` to confirm `## A1:` exists, but runs `pat.sub(..., s, count=1)` on the **unstripped** string `s`. Because `## A1:` and `- status: proposed` appear inside the template's HTML comment first, `count=1` rewrites `- status: approved` **inside the HTML comment** and leaves the actual `## A1:` section at `status: proposed`! Then `ra.py status` still shows `proposed A1`. (`evals/run.py:94` missed this because it overwrites `plan.md` without the template comment.)
- **Second bug in the same regex:** `pat = re.compile(rf"(^## {re.escape(aid)}:.*?^- status:)[^\n]*", re.S | re.M)` (`scripts/ra.py:121`) uses `.*?` with `re.S`, which crosses `^## A\d+:` section boundaries. If `A1` is missing a `- status:` line, `set_status(d, ["A1"], "approved")` matches from `## A1:` through `## A2:\n- status:` and silently overwrites `A2`'s status.
- **Concrete fix:**
  1. In `scripts/ra.py:116-127`, match only outside HTML comments and within the target section boundary (`rf"(^## {re.escape(aid)}:[^\n]*\n(?:(?!^## A\d+:)[^\n]*\n)*?- status:)[^\n]*"` applied only to the non-comment slice, or strip/replace the template comment when writing sections).
  2. Add a test in `evals/run.py` that appends `## A1:` to the `ra.py init`-generated `plan.md` (keeping the HTML comment) and verifies `ra.py gate DIR G3 "..." --approve A1` updates `sections(d / "plan.md", "A")["A1"]["fields"]["status"] == "approved"`.

### 2. [FAILURE MODE LET THROUGH / Q2, Q3] `verdict.md` validation in `ra.py check` lets through omitted controls/variants/counts and unsourced numbers, while firing false positives on valid folders
- **Where:** `scripts/ra.py:31-32, 280-298`, `templates/research/verdict.md:7-14`, `evals/run.py:124-126`.
- **Problems:**
  1. **Omitted mandatory fields pass (`ra.py:285-291`):** `check()` only verifies that `rule` and `verdict` are non-empty in `verdict.md`. It never checks that `result`, `controls`, `variants`, `analyses run`, or `rival` exist or are non-empty! An agent can delete `controls`, `variants`, `analyses run`, and `rival`—or leave them as literal `<...>` template placeholders—and `ra.py check` exits `0`. In fact, `evals/run.py:124-126` itself passes `ra.py check` with a `verdict.md` that omits `controls`, `variants`, `analyses run`, and `rival`, directly bypassing `references/research-rules.md` rules #8 (F2, variant spread), #9 (F5, negative/positive controls), F1 (count all runs including failed), and F11 (nearest rival). Even `- result: <what came out, each number with its [source]>` left untouched from the template passes because `empty()` is never called on `result` and the placeholder contains `[source]` and no digits.
  2. **One `[...]` masks unlimited unsourced numbers (`ra.py:295-296`):** `if nums and not SOURCE.search(val):` only checks whether *at least one* `[...]` appears *anywhere* in the field value `val`. If `result` is `- result: gOSI 0.52 [outputs/run1/a.json:gosi], plateau rate 0.81, firing 14.2 Hz`, `SOURCE.search(val)` is truthy, so `0.81` and `14.2` pass without a source (violating `references/research-rules.md` #2 / E2). Even `[TODO]` or `[n/a]` satisfies `SOURCE = re.compile(r"\[[^\]]+\]")`. Numbers inside `rival` (`ra.py:293`) or in lines below the bullet fields are not checked at all.
  3. **False positives on valid `verdict.md` (`ra.py:32, 293-298`):**
     - `analyses run` is not in the skip list `("rule", "verdict", "rival")` (`ra.py:293`), yet `templates/research/verdict.md:12` defines it as `- analyses run: <count, including failed ones>` (without `[source]`). Writing `- analyses run: 3 (0 failed)` triggers a false positive: `verdict.md A1 'analyses run': numbers (3, 0) without a [source]`.
     - For a `failed` analysis (which `ra.py:278` requires in `verdict.md`), writing `- result: crashed twice with OOM after 12 min (exit 137)` fails because `12` and `137` have no run-output `[source]`.
     - `NUMBER = re.compile(r"(?<![\w.§#-])[-−]?\d+(?:\.\d+)?(?:\s*%)?(?![\w])")` (`ra.py:32`) matches `/3` in `L2/3` (`/` is not in `[\w.§#-]`), forcing a `[source]` on anatomical names like `L2/3`.
- **Concrete fix:**
  1. Require `result`, `controls`, `variants`, `analyses run`, and `rival` to be non-`empty()` for every `done` analysis in `verdict.md` (and require `result` and `analyses run` for `failed` analyses). Update `evals/run.py:124-126` to include those fields.
  2. Add `"analyses run"` to the source-check skip list (`ra.py:293`), or require `[RUNS.md]` in the template for `analyses run`; skip source requirements on `result`/`controls`/`variants` when the analysis status in `plan.md` is `failed`.
  3. Add `/` to the negative lookbehind in `NUMBER` (`r"(?<![\w.§#/-])..."`) so `L2/3` is not parsed as the number `3`.
  4. Tighten `SOURCE` to require a file/path or section citation (`r"\[(?:[^\[\]]*[/§:][^\[\]]*|RESULTS[^\]]*|RUNS[^\]]*|L\d+[^\]]*)\]"`), and check that each clause/segment with a number (e.g. split on `;` or `,` outside brackets) or every number is followed by a `[source]`, rather than `not SOURCE.search(val)` across the whole line.

### 3. [FAILURE MODE LET THROUGH / Q1, Q2, Q3] Stage 6 audit (`verify/audit-N.md`) is never checked by `ra.py check` or `ra.py status`, and its invocation/format is unspecified
- **Where:** `SKILL.md:65, 73`, `scripts/ra.py:100, 174-186, 219-303`, `references/research-rules.md:31` (#5 / E1, E8, G2, G6).
- **Problem:** `references/research-rules.md` #5 highlights that auditing from logs and code is one of the strongest empirical protections (82% vs 55%). `ra.py init` (`ra.py:100`) creates `verify/`, `SKILL.md:65` requires a fresh checker report in `verify/audit-N.md` before any write-up, and `SKILL.md:73` instructs the agent to run `ra.py check DIR` *"before each gate and before the hand-over"*. However:
  1. `ra.py check` never inspects `verify/` at all—an agent can skip the audit completely and `ra.py check` exits `0`.
  2. `stage(d)` (`ra.py:179-180`) lumps stages 6 and 7 together (`"6-7 verdict, audit and write-up"`) as soon as all analyses in `plan.md` are `done`/`failed`/`dropped`, even when `verdict.md` is empty and `verify/` has no `audit-*.md`.
  3. `SKILL.md:65` does not specify the required structure of `verify/audit-N.md` (e.g. checker model/harness, files inspected, per-analysis number & rule check, `status: pass | disagreement`) so `ra.py check` can verify it.
- **Concrete fix:**
  1. Add a brief template or required fields for `verify/audit-N.md` in `SKILL.md:65` (`- checker: <model/agent>`, `- inputs: <plan.md, log.md, verdict.md, code/logs>`, `- status: pass | disagreement`, `- findings: ...`).
  2. In `scripts/ra.py`: split `stage(d)` into `"6 verdict"`, `"6 audit (verify/audit-N.md)"`, and `"7 write-up (ready for hand-over)"`; in `check(d)`, when all non-dropped analyses have sections in `verdict.md` (or via a `ra.py check --stage 7` / hand-over check), require at least one `verify/audit-*.md` with `- status: pass`.

### 4. [FAILURE MODE LET THROUGH / Q2, Q3, Q4] `ra.py gate` records gates without checking prior-stage artifacts, and post-Gate-3 edits to `plan.md` can silently alter pre-registered rules without a deviation
- **Where:** `scripts/ra.py:130-160, 228-235, 284-289`, `SKILL.md:29, 39, 52, 58`.
- **Problems:**
  1. **`cmd_gate` does not validate stage prerequisites (`ra.py:130-160`):** `ra.py gate DIR G1 "yes"` succeeds when `question.md` is still 100% `<placeholders>`; `ra.py gate DIR G2 "yes"` succeeds when `hypotheses.md` has 0 hypotheses and `question.md` has no `literature:` folder; `ra.py gate DIR G3 "yes" --approve A1` succeeds when `A1` in `plan.md` still has `<placeholders>` for `decision rule`, `negative control`, `positive control`, and `cost`.
  2. **Mutable `plan.md` after Gate 3 lets HARKing / threshold tuning through (`ra.py:284-289`, `references/research-rules.md` #3, #4, #7):** `ra.py check` verifies `_norm(v["fields"]["rule"]) != _norm(rule_plan)` by comparing `verdict.md` against the *current* `plan.md`. If an agent edits `decision rule`, `metric`, or `data` in `plan.md` after seeing run outputs (and copies the edited rule into `verdict.md`) without running `ra.py deviation`, `ra.py check` passes with 0 problems!
  3. **Re-gating G3 cannot drop a previously approved analysis (`ra.py:76-83`):** `approved(d)` unions (`|=`) all `approve` lists across `G3` lines in `log.md` and ignores `drop` lists on later `G3` lines.
- **Concrete fix:**
  1. Have `cmd_gate` (`ra.py:130-160`) run the stage-specific checks before appending to `log.md` (G1: `question.md` required fields filled; G2: `literature` filled in `question.md` and $\ge 3$ complete hypotheses in `hypotheses.md`; G3: every `--approve`d analysis in `plan.md` has all `PLAN_FIELDS` filled).
  2. When `cmd_gate` records `G3 --approve A1`, record a short digest or snapshot of `A1`'s `decision rule` (or `PLAN_FIELDS`) in `log.md` (or check that any change to `decision rule` after G3 has a matching `deviation A1` line in `log.md`).
  3. In `approved(d)` (`ra.py:76-83`), process `G3` lines sequentially: `ids |= approved_in_line; ids -= dropped_in_line`.

### 5. [AMBIGUITY & FALSE POSITIVE / Q1, Q3, Q4] Gate 2 selects hypotheses (or stops the loop), but `hypotheses.md` and `ra.py` have no way to mark selected vs unselected hypotheses
- **Where:** `SKILL.md:37-43`, `templates/research/hypotheses.md:7-12`, `scripts/ra.py:233-242`.
- **Problems:**
  1. **Cross-reference catch-22 between Stage 3 and Stage 4 (`SKILL.md:37, 39, 73`, `ra.py:237-242`):** Stage 3 (`SKILL.md:37`) is before Gate 2 and requires `- analysis: <A-ids able to produce that result>` in `hypotheses.md` (`ra.py:237`), before `plan.md` is written in Stage 4 (`SKILL.md:43`). Then at Gate 2 (`SKILL.md:39`), *"The person picks the hypotheses to take forward, or stops the loop because the literature answered it."* Once the agent writes `plan.md` in Stage 4 for only the *selected* hypotheses (say `H1, H2` tested by `A1`), any unselected hypothesis (`H3`) that named `A2` now fails `ra.py:240-242` (`hypotheses.md H3: analysis A2 is not in plan.md`)!
  2. **No record of which hypotheses passed Gate 2 (`ra.py:130-160`):** Unlike Gate 3 (`--approve A1,A3 --drop A2`), Gate 2 (`ra.py gate DIR G2 "<words>"`) does not record which hypotheses were selected or dropped, nor whether the loop was stopped at Gate 2 because the literature answered the question (`SKILL.md:39`).
- **Concrete fix:**
  1. Add `--approve H1,H2 [--drop H3] [--stop]` to `ra.py gate DIR G2` (or a `- status: proposed | selected | dropped` field in `templates/research/hypotheses.md`).
  2. Before Gate 2, allow `- analysis:` in `hypotheses.md` to describe the needed analysis conceptually or by provisional ID; after Gate 2, enforce `aid in plan` (`ra.py:240-242`) only for `selected` hypotheses, and if `--stop` was passed at G2, have `stage(d)` report `"stopped at G2 (answered by literature)"` and `check(d)` not require `plan.md`.

### 6. [GATE DESIGN / Q4] Stage 4 (`SKILL.md:50, 52`) tells the agent to write analysis scripts and run simulated-data/smoke tests *before* Gate 3 approves which analyses to run
- **Where:** `SKILL.md:50, 52`, `templates/research/plan.md`.
- **Problems:**
  1. **Premature work before human gate (`SKILL.md:50, 52`):** At Gate 2 the person only picked *hypotheses*, not the specific analysis designs. `SKILL.md:50` (inside `## 4. Plan (rules D) → gate 3`) says: *"Write the analysis script first and run it on simulated data where possible (D9)"*, and line 52 says *"Before this gate, only smoke runs that test a script (seconds to minutes, within the project's memory budget)."* Writing full scripts and running synthetic/smoke tests for every proposed analysis (`A1, A2, A3...`) before Gate 3 spends significant agent tokens, wall time, and compute on analyses the person may drop or redesign at Gate 3 (as `SKILL.md:52`'s own `--drop A2` example shows).
  2. **Missing cost table and stop rules in `plan.md` (`SKILL.md:52` vs `templates/research/plan.md`):** `SKILL.md:52` says *"Show `plan.md`, its cost table and the stop rules (D10, H2)."* But `templates/research/plan.md` has no cost summary table and no stop-rules field (only per-section `- cost:` lines).
  3. **Post-Gate-3 deviations (`SKILL.md:58` vs `59`) and project `DECISIONS.md` (`SKILL.md:63`):** `SKILL.md:58` allows logging a deviation to *"data, splits, metric, threshold, seeds or design"* (even *"after seeing any outcome"*) via `ra.py deviation`, whereas line 59 says *"or you would change the evaluation. Write it into `decisions.md` and ask."* Any change to data, splits, metric, threshold, or decision rule after Gate 3 is a change to the evaluation and must require the person's approval before continuing, not just a log line. Likewise, in Stage 6 (`SKILL.md:63`, *"a DECISIONS entry when a choice follows"*), the agent should draft or recommend the project `docs/DECISIONS.md` entry for the person rather than unilaterally committing the project decision before the person sees the verdict.
- **Concrete fix:**
  1. Move `SKILL.md:50` (*"Write the analysis script first and run it on simulated data where possible (D9)"*) to the start of **Stage 5 (Run)** for the *approved* analyses (before running on real/held-out data), leaving only feasibility/cost-check one-liners before Gate 3.
  2. Add a markdown cost-summary table and `- stop rules:` line to `templates/research/plan.md`.
  3. Clarify in `SKILL.md:58-59` that operational deviations (e.g. a crashed seed replaced before seeing outcomes) are logged with `ra.py deviation`, while any change to data, splits, metric, threshold, or decision rule requires escalating in `decisions.md` and re-gating before running.

### 7. [BUGS & WEAK CHECKS IN `ra.py` / Q2, Q3] Nested placeholders in `question.md`, hyphenated keys, unverified `cannot answer` / `literature` / `RESULTS.md` / `RUNS.md`
- **Where:** `scripts/ra.py:30, 53, 63, 86-87, 228-230, 267-275`, `templates/research/question.md:10, 13-14`.
- **Problems:**
  1. **`PLACEHOLDER` regex fails on `templates/research/question.md:13-14` (`ra.py:30, 86-87`):** `PLACEHOLDER = re.compile(r"<[^<>\n]{3,}>")` forbids `<` and `>` inside `<...>`. In `templates/research/question.md:13-14`, the placeholders are `<docs/literature/<topic>/ once stage 2 runs>` and `<docs/writeups/<topic>/ once stage 7 runs>` (nested `<topic>`). `ra.empty()` returns `False` on both, thinking the untouched template placeholders are filled!
  2. **Hyphenated field names dropped (`ra.py:53, 63`):** `r"^- ([a-z][a-z ]*?):\s*(.*)$"` does not match `-`, so `- write-up:` (`templates/research/question.md:14`, pilot `question.md:14`) is silently omitted from `fields_of()`.
  3. **`cannot answer` and `literature` are never checked (`ra.py:228`):** `ra.py:228` checks `("question", "type", "decision", "claim type", "budget", "stop rules")`, omitting `"cannot answer"` (required by `SKILL.md:27`, rule A6) and omitting `"literature"` even after Stage 2 / Gate 2 (`SKILL.md:33`, rule B5). Nor does `ra.py check` verify that the cited `docs/literature/<topic>/` directory exists or that `L<n>` IDs in `hypotheses.md` (`source: L8, L26`) exist in its `ledger.md`.
  4. **`results` check silently bypassed if `§` is omitted (`ra.py:267-269`):** `for n in re.findall(r"§\s*(\d+)", f.get("results", "")):` does zero iterations if the agent writes `- results: docs/RESULTS.md section 55` (without `§`), passing without checking `docs/RESULTS.md`! And if a subsection is `§8b` (as in `simple_complex_v1/docs/RESULTS.md:320`, `### 8b.`), `re.findall(r"§\s*(\d+)")` extracts `8` and only matches `^## 8\.`.
  5. **`runs` check false positive on backticks or notes (`ra.py:273-275`):** `re.split(r"[,;\s]+", f["runs"])` splits on spaces and keeps punctuation, so `` `mel_nmda_sweep_a` `` or `mel_nmda_sweep_a (3 seeds)` fails with `run (3 is not in docs/RUNS.md`.
- **Concrete fix:**
  1. Change `PLACEHOLDER` (`ra.py:30`) to `re.compile(r"<[^\n]{2,}>")`.
  2. Allow hyphens in field names (`ra.py:53, 63`): `r"^- ([a-z][a-z -]*?):\s*(.*)$"`.
  3. Add `"cannot answer"` to `ra.py:228`, and when `"G2" in g`, check that `q.get("literature")` is non-`empty()` (and if `project_root(d)` exists, check that the referenced path exists).
  4. In `ra.py:267-269`, require `re.findall(r"(?:§|section\s*)\s*(\d+[a-z]?)", f.get("results", ""), re.I)` to be non-empty when `res` exists, and match `rf"^#{{2,3}} {re.escape(n)}\."`.
  5. In `ra.py:273`, strip parentheticals and backticks before splitting run IDs (`re.findall(r"[A-Za-z0-9_./-]+", re.sub(r"\([^)]*\)", "", f["runs"]))`).

## Direct Cross-Reference by Brief Question

1. **Could an agent follow `SKILL.md` cold?** Mostly yes for `--entry project` up to Gate 1, but it will hit bugs/ambiguities at: `templates/research/plan.md` HTML comments breaking `ra.py gate G3` (**Finding 1**); whether to inspect existing `docs/literature/` before Gate 1 (**Finding 8.1**); how to record selected vs dropped hypotheses at Gate 2 without breaking `ra.py check` (**Finding 5**); where to record reviewer-question triage for `--entry review` and how `--entry idea`/`paper` sequence Stages 1–3 (**Finding 8.3–8.4**); how to format `verify/audit-N.md` (**Finding 3**); and what *"taken by script, never typed"* requires mechanically (**Finding 8.3**).
2. **Does the procedure prevent the failures in `references/research-rules.md`?** The design covers all 12, but `ra.py check` currently lets through: **unaudited reports** (`verify/` is never checked, **Finding 3**); **omitted controls, variant spread, run counts, and rival comparisons in `verdict.md`** (`check()` only checks `rule` and `verdict`, **Finding 2.1**); **unsourced numbers sharing a line with one `[source]` or placed in `rival`** (**Finding 2.2**); **post-Gate-3 edits to `decision rule` in `plan.md` without a logged deviation** (**Finding 4.2**); **passing gates on unfilled files** (**Finding 4.1**); and **unverified literature folders / `cannot answer` / `results` without `§`** (**Finding 7.3–7.4**).
3. **`ra.py` bugs, weak/strict checks, and false positives:**
   - *Bugs:* `set_status` edits the template HTML comment instead of the real section and can cross section boundaries (**Finding 1**); `PLACEHOLDER` fails on nested `<topic>` in `templates/research/question.md:13-14` (**Finding 7.1**); `fields_of` drops hyphenated `- write-up:` (**Finding 7.2**); `approved()` ignores subsequent `G3 --drop` (**Finding 4.3**).
