# Herdr delegate

You (the lead) hand a self-contained step to a helper agent running another CLI (or Claude Code under another account) on another subscription, in a terminal herdr-core keeps alive. The person can watch and type into every helper from the Herdr app. You launch it, approve or escalate its permission prompts, answer its questions, read its report, and review the work before using it. Use it for long, self-contained work: research, code to a spec, trying many options, sweeps. Don't use it for steps that need this conversation's context, for steps under about 5 tool calls (briefing costs more than doing), or for a decision that belongs to the person.

`hc --skill` is the full manual for herdr-core. This skill adds the helper CLIs, their quirks, and the judge role. If `hc` isn't on PATH, say so and use the harness's own subagents instead.

Helpers are **templates** named `<provider>-<tier>` (`kiro-standard`, `agy-deep`, `claudeuni-light`; `hc templates` lists them), rendered from configuration by `scripts/helpers.py render`; a provider whose CLI is not installed is skipped everywhere. Pick one with `helpers.py pick` (see "Which helper"); the detail behind the names is in `references/` (list at the end of "Which helper").

## Steps

1. **Check.** `echo $HC_TERMINAL_ID` is your address (the helpers report to it). If it's empty, you're not in an hc terminal and helpers can't reach you: use "Without Herdr (direct mode)" below, or the harness's subagents when no helper has a headless command. Then pick a template (see "Which helper"). For a model-router plan step with where = "helper", pass the order the router's rules give for that tier: `helpers.py pick <a,b,c>`; when it finds none, run the step with the Agent tool as the rules say.
2. **Brief.** Self-contained: goal, exact scope (files and folders it may touch), what to return, and where (a file path for anything over a few lines). Include "Report to the lead (<your address>) with hc send". For code: a branch or worktree of its own, and whether it may commit. The template body already covers the reporting protocol, scope discipline and honesty.
   - **Put the brief inside `--cwd`** (or send it inline): Copilot stops at an "Allow path access" dialog for a brief file outside its workspace.
   - **Launch it where it works:** `--cwd` is the helper's workspace, and Kiro cannot start a server or write outside it, so launch in the repo or worktree it must run things in.
   - **A worktree for code** has only tracked files: link each git-ignored directory the code reads (`git status --ignored` lists them: `data/`, `outputs/`, `external/`, a local config) and, when the package is installed editable from the main checkout, set `PYTHONPATH=src`.
   - **Config-writing code:** say to set the override inline in every command (`XDG_CONFIG_HOME=... cmd`); an `export` does not persist between a helper's shell calls, and a test once wrote to the real `~/.config`.
   - **Kiro helpers cannot push or pull over HTTPS** (its policy blocks publishing to a shared branch): the lead pushes.
   - **Long jobs outlive the helper only in their own session.** If the helper must start a job that keeps running after you kill it (a sweep, a queue), the brief says to launch it with `setsid` or Python `start_new_session=True`, not plain `nohup`: `hc kill` takes down the helper's whole process tree.
   - **Brief for cost:** the helper's quota goes on context it re-reads every turn. Point at files with line ranges or a lookup command instead of "read X"; pick the lowest tier that fits (standard for code to a spec, deep only for open judgment); one session per batch, not one long session for many; say how many screenshot or test rounds are enough. Start long runs (a queue, a sweep) yourself and brief a helper only for the analysis: one that waited for a 2 h queue inside its session cost 393 AIC against 70-150 for comparable tasks. Ask for checks to be batched into one script file: audits with many shell commands cost 8-15% of a weekly quota, read-only passes 2-3%.
   - **For agy, scripts go in files:** agy approves per command prefix, so multi-line `python -c`, heredocs, `$( )` and `||` ask every time (about 20 prompts in one audit). Brief it to write each check to a scratch file in its workspace and run `python <file>`, one script for all the quote checks.
3. **Launch.** `hc run --json --bg --name <short-name> --cwd <dir> <template> "<brief>"`. Check `first_message.sent`. If false, `hc read <name>`: a first-run dialog is probably showing (see CLI quirks). Answer it, then `hc send <name> "<brief>"`. Never relaunch blindly. Copilot always shows false (see quirks).
4. **Keep working.** Then `hc wait --children any` (or `all`). `reason: message` means a report arrived as your next input. `timeout` is a check-in, so wait again. Never sleep or poll, and never leave the wait running in the background while you sit idle.
   - **A Copilot helper is running:** hc can't see it blocked (no status), so a long wait leaves its prompts to the person. Wait with `--timeout 60`, and after every check-in run `helpers.py prompt <name> ...` for each Copilot helper: exit 0 means one is waiting, and it prints the command and the options. Judge it as in step 5. Example (2026-11-01): a lead in a 15-minute wait left three Copilot shell prompts for the person to approve by hand.
5. **Judge prompts.** Kiro and Copilot run their own judge, so prompts reach you mostly from agy, or when a judge is unsure. Copilot's judge passes up compound shell scripts (heredocs, loops, `rm`, `curl` in one command) and doesn't decide them. When hc says a helper is `blocked (permission)`, or `helpers.py prompt` finds one, read the exact command (`hc read <name> --lines 30`; agy may show only the first line of a multi-line script: read more lines, and if the rest stays hidden decline and ask the helper to put it in a file).
   - Navigate options with `hc keys <name> down` before `enter`, and `escape` to decline. For a safe command the helper will repeat (`curl` reads during research), pick Copilot's "don't ask again for … in this directory" or "approve all URLs from …" option, so it asks once.
   - **Approve yourself** (`hc keys <name> enter` on the "Yes" option) when it's inside the brief's scope and reversible: reads, builds, tests, writes inside its scope, `hc send` to you. For `hc send`, pick the "always allow in this conversation" option so it asks once.
   - **When your own approvals are refused:** a lead in Claude Code's auto mode may have its `hc keys` approvals of a helper's prompt refused by its own permission classifier ("Auto-Mode Bypass", 2026-11-13). Do not retry around it: ask the person to answer in the Herdr app, and for the next helper prefer one whose judge works on its own (Kiro, Codex, a Claude account in auto mode) over Copilot or agy.
   - **Ask the person** when it's outside scope, irreversible or outward-facing (push, delete outside scope, network writes, credentials, installs), or you're unsure. Quote the command in one line.
   - `blocked (auth)` often clears by itself (token refresh): wait once, then read. For Kiro, if it persists, its login has gone stale: see "Kiro's login goes stale" below.
   - Never `hc send --force` past a prompt.
6. **Answer questions.** Questions arrive as `<hc from="tN name">` messages. Answer from what you know with `hc send <name> "..."`. Bring the person only decisions that are theirs.
7. **Review.** A report is a claim. Read the actual files or diff before telling the person it worked, and spot-check light-tier results. Example (2026-10-31): a Kiro helper sent "wc -l prints 3" before running `wc`, then corrected itself. If the result is weak, rerun one tier up.
8. **Clean up.** Once you've accepted the work, first read what the helper used: `helpers.py usage <name>` prints `{"provider", "amount", "unit"}`: Kiro credits and Copilot AIC from its screen; for a Claude account and Codex, the rise of its 7d percent since `pick` chose it (`% of 7d`; nothing when a side is unknown or the rise is not positive); for agy, the drop in its model group's weekly limit since `pick` chose it (from `agy -p /usage`, in percentage points). Those two are the whole account's change, not the helper's: every session on the account in that time is in it, and helpers that ran in parallel on one account (or one agy group) each print the same shared rise, so report the largest figure once for the batch, never the sum (three helpers printing 15, 18 and 19 % used about 19 %, not 52 %), and say it is account-wide if the person's other sessions were using the account. Nothing is printed when none is known. Hand that JSON on as is (model-router: the `usage` of the step's done item); when it prints nothing, report no usage, never 0 or a guess. Then `hc kill <name>; hc rm <name>`, only for helpers you started. Before `hc kill`, if the helper started a job that must keep running, check it is outside the helper's process tree (`ps -o pid,pgid,sid,command`: its session differs from the helper's) and confirm it is still alive afterwards; otherwise relaunch it yourself.

## Which helper

Tiers: light = mechanical work with a clear rule, standard = following detailed instructions, deep = open judgment. **Second** (named `argon` before 2026-11-19, still accepted) is a second opinion from another model family: use it to review a plan or a result, or to answer the same question independently, not as a cheaper standard. `pick second` tries agy first (Gemini 4 Neon high), and `pick` skips any template whose model the last `helpers.py models` found not offered (Copilot would silently swap it, e.g. Gemini 4 Argon to Sonnet).

**Choosing for model family.** When a step is a review, a read or an independent check, prefer a helper from a different model family than yours if one is available (`agy-standard` is Gemini 4 Hydrogen high, rated by the owner about Sonnet 5.5 high: a different-family standard helper); if none is, use what is available and do not block on it (a Gemini reader via agy caught factual errors that Claude readers missed, three times in research-writing). When a helper is chosen for its model family, check the model it reports at launch (Copilot prints "Model ... not available. Using X instead" and its status bar shows the model) and treat a fallback as the wrong helper: kill it and pick another.

**Copilot Fusion** (`copilot-fusion-high` / `-max`: a router across Claude and GPT-6 models, not a model) is opt-in: it is in no default order, and `pick fusion` (Max, then High) or a named template uses it. Use it for large, well-scoped coding steps where cost and speed matter more than knowing the model; the status bar shows "Copilot Fusion · High" or "· Max"; review its diffs (discarded drafts' edits stay); keep the pinned templates for anything that must be a known model.

Run `scripts/helpers.py pick <tier>` (light, standard, deep, second), or `pick a,b,c` for your own order of **template** names (`kiro-standard,agy-standard`, not `kiro,agy`: a name with no template is reported on stderr). It prints the first template whose CLI is installed and whose provider has quota, or exits 1 when there is none: then use the harness's own subagent and say so. The default order comes from each provider's `order` in the config (lowest first; shipped: Kiro 10, Copilot 20, Codex 30, agy 40, a Claude account 50; `tier_order` moves a provider for one tier). Put providers with a big quota early and a provider with a small quota late, so it is used only when the others are out; change an order with `order` in your override. A provider with a quota source (a Claude account's readings, Codex's usage endpoint or latest session file) is skipped while it is out of quota. When a helper hits a quota error ("exceeded your monthly quota", credits used up), run `helpers.py out <provider>`: it marks the provider out until the 1st of next month, and the mark clears by itself. `helpers.py status` shows everything. `back <provider>` clears a mark early.

**When the person is away** (asleep, AFK), prefer a helper whose judge works unattended (Kiro's approve-for-me, Codex's auto review, a Claude account's auto mode): Copilot's assisted judge escalates ordinary read commands every few seconds and cannot find genome skills by `/name`, so it needs a present lead.

**Kiro's login goes stale** after about 8 to 12 hours; that is expected, not a fault. Signs: hc shows the helper `blocked (auth)` and waiting once doesn't clear it, or its screen asks to log in or says the token expired. Then:
- If the person is around, ask them in one line to log in (`! kiro-cli login` at your prompt), wait, then `helpers.py back kiro` if you had marked it and carry on with the same helper.
- If they are away (asleep, or they said they're AFK), don't wait: `hc kill`/`hc rm` the helper, run `helpers.py login kiro` (a mark with no expiry, so `pick` skips Kiro), and relaunch with the next pick. Tell them when they're back. The mark clears itself: `pick` and `status` run `kiro-cli whoami` and drop it once Kiro is logged in again.

## Without Herdr (direct mode)

When `$HC_TERMINAL_ID` is empty, helpers still run, one shot per brief. Pick as usual (`helpers.py pick <tier>`: it needs no `hc`). Write the brief to a file inside the workspace, then run `helpers.py run <template> --brief <file> --cwd <dir>` in the background (Claude Code: Bash with `run_in_background`) and wait for its notification. The last stdout line is JSON (`exit`, `out`, `log`, `seconds`, `usage`): read the `out` file (the helper's final report), review it as in step 7, and hand `usage` to model-router's done item as is (omit it when null). `helpers.py config` marks each provider `"direct": true` when it has a headless command and its CLI is installed; a Fusion tier has none. Lost against a terminal helper: no live screen, no approvals mid-run (what the allowlist does not cover is refused, so the helper reports it as blocked), no questions or replies, and the run stops after `--timeout` minutes (default 60, exit 124). Details and per-CLI flags: `references/providers.md`.

## CLI quirks (measured 2026-10-31)

- **`hc send` wraps text in an `<hc>` tag**, so slash commands sent that way arrive as plain text. Type them as keys instead: `hc keys <name> / m o d e l` then `hc keys <name> enter`.
- **Dialogs on a fresh folder or install:**
  - agy: "Do you trust the contents of this project?" Answer `enter` (Yes) for a folder named in your brief.
  - Copilot: "Confirm folder trust". Answer `enter` (Yes, this session).
  - Kiro v3: the templates pass `--trust-workspace`, so no dialog.
- **Copilot never reports a status to hc** (status stays null). Its `first_message.sent` is always false, and `hc wait` can't see it finish. After launching: `hc read`, answer the trust dialog, `hc send` the brief, then rely on its `hc send` report, checking for prompts at every 60-second check-in (step 4).
- **Copilot silently swaps an unavailable model** (for example Haiku 5.5 on some plans becomes Sonnet 5.5): check the model line on its screen.
- **Without the template's protocol text, a small model treats `<hc>` messages as prompt injection** and refuses (Kiro on Haiku 4.5). Always launch through a template, or put the protocol paragraph in the brief.
